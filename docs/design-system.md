# 设计系统

Mac 与 iPhone 共用 `Sources/CourtApp/Views/CourtStyle.swift` 中的令牌和组件。新界面先复用这里的值；确需新值时先加令牌，再在视图里引用，不直接写颜色、圆角、透明度或间距。

## 令牌

| 类别 | 令牌 | 值 / 用途 |
| --- | --- | --- |
| 品牌色 | `green` | 主按钮、选中、实时状态、强调文字。不用于数据系列 |
| 表面 | `background` / `panel` | 页面底色 / 面板底色 |
| 表面 | `raised` | 白 5%：面板内的指标块、次按钮、状态胶囊、分段选择器的底 |
| 表面 | `inset` | 黑 20%：输入框、列表行、图表底 |
| 文字 | 白色 / `muted` | 正文 / 次要说明（面板上对比度约 7:1）。不再给 `muted` 叠透明度 |
| 描边 | `border` | 白 9% |
| 语义 | `warning` / `warningFill` | 需要注意：中断、暂停、球场未识别、错误。总与图标或文字同时出现；`warningFill`（橙 8%）是错误横幅的底 |
| 语义 | `recording` | 仅用于 REC 录像标识 |
| 选中 | `selectedFill` / `selectedStroke` | 绿 10% / 绿 50%：选中的逐拍行、历史中选中的一拍 |
| 选中 | `segmentSelected` | 白 14%：`CourtSegment` 与倍率按钮的选中项 |
| 遮罩 | `scrim` | 黑 55%：画在视频上的按钮、倍率条、标签的底 |
| 遮罩 | `blockingScrim` | `background` 75%：保存或关闭期间盖住整页 |
| 球场图 | `courtSurface` / `courtLine` / `courtNet` | `#0E2921` / 白 55% / 白 80%（虚线）：俯视落点图。浏览器看板使用同样的值 |
| 圆角 | `Radius.panel` 22 · `card` 16 · `control` 13 · `field` 11 | 面板与视频 / 卡片 / 按钮与列表行 / 输入框与小指标块 |
| 间距 | `Space.xs` 4 · `s` 8 · `m` 12 · `l` 16 · `xl` 24 · `xxl` 32 | 栈间距与内边距只用这六档。面板内边距 `xl`，面板之间 `l`，同组控件之间 `s` |

字号使用系统动态字体（`.title3`、`.caption` 等），以支持辅助大字号；固定字号只用于图标与测速牌读数。

全屏测速牌是场边远看的读数，当前球速是整块牌子，其他都是次要的：数字用 SF Pro 窄体粗体等宽数字（比圆体在同样宽度下高约 30%），按字形的大写高度而不是行高计算字号，三位数能放下的最大字号铺满读数区（`SpeedHeroLayout`）；字号只随窗口变、不随读数的位数变，避免 96 看起来比 156 大。单位 km/h 放在数字旁边或右下方，取让数字更大的那种。「发球」模式不再左右分栏：MAX / AVG / MIN 只占一行，趋势是没有坐标轴的细线条（高度约为牌子的 9%，36–84 pt），旁边一个小图例（NOW、AVG），宽屏并排、竖屏上下叠放，牌子矮于 280 pt 时收起（`ServeBandLayout`）。说明文字只留底部一行小字：`#7` 这样的序号和「模型估算」；完整中文说法放在读屏标签里。读数与趋势里的「当前值」用品牌绿（同一个数字），其余历史点为白色半透明，平均为灰色虚线；这是品牌绿唯一作为数据标记的地方。测速牌整体把动态字体上限设为 `accessibility2`：读数本身是随窗口缩放的固定字号，周围的切换、状态与「模型估算」若不设上限会把读数挤小；读屏标签不受影响。新读数到来时数字用 `.numericText()` 滚动，并按拍（不是按数值）短暂高亮一次，所以连续两拍速度相同也能看出更新；「减弱动态效果」下不滚动、不放大，只保留高亮。浏览器看板的测速牌用同样的规则（`prefers-reduced-motion`）。

## 动效与触感

- 动效只用来说明「变了」：测速牌新读数、提示横幅出现与消失（淡入淡出）。都尊重「减弱动态效果」。
- 触感（iOS `.sensoryFeedback`）只跟随**已确认**的状态变化，不跟随点按：看板发出的命令要等机位回发记录后才变，所以开始 / 继续（中）、暂停（轻）、结束（重）、意外中断（警告）都是机位确认过的；打标记成功为 success；机位开始 / 停止采集为中 / 轻。测速牌上每个新的有效读数轻触一下，只在测速牌上。浏览器看板在「已打标记」提示时调用 `navigator.vibrate?.(30)`（支持的浏览器才会震）。

## 组件

| 组件 | 用途 | 约定 |
| --- | --- | --- |
| `CourtPanel` | 标题 + 内容的面板 | 内边距 `xl`，辅助字号下减为 `l`，把宽度留给文字；`accessory:` 放在标题行右侧，只放一个 `CourtLinkButton`、44pt 图标按钮或 `CourtStatus`；不要再用负内边距手拼标题行，也不要在面板里另写一行 `.headline` 当标题。App 里已没有英文 eyebrow（记录详情的 ANALYSIS RECORD / REPLAY / SESSION TIMELINE / MANAGE 已去掉），参数只为兼容保留，不再使用；并排面板用 `fillHeight` 等高 |
| `CourtButton` | 主 / 次 / 结束类按钮 | 高度不小于 46pt，整块圆角区域可点；`primary` 只给当前状态下最重要的一步（例如未连接时的「连接机位」） |
| `CourtBarButton` | 底部控制条的按钮 | 图标在上、短标签在下，等宽，至少 52pt 高；颜色同 `CourtButton`。只在常规字号使用，辅助字号下同样的操作回到页面里，用 `CourtButton` |
| `CourtSegment` | 二到四个选项的分段选择 | `raised` 底、每段至少 44pt、选中项 `segmentSelected` 加粗白字，放不下时自动改为竖排，竖排时标签可折成两行或略缩小，不把页面撑宽；带 `isSelected` 读屏特性。测速牌的「球速 / 发球」、机位的「记录 / 分析 / 设置」、历史的「按记录查看 / 球速与落点查询」和首页的「分析模型」都用它；不用系统的分段 `Picker` |
| `CourtLinkButton` | 面板标题右侧的文字操作 | 44pt 高的可点区域，不只是文字本身 |
| `CourtIconButton` | 方形图标按钮（历史记录、返回） | `raised` 底，至少 44pt，随字号用 `@ScaledMetric` 放大（上限 68pt）；读屏标签写操作名 |
| `CourtTextButton` | 只有文字的按钮：sheet 的「完成」「取消」、进度旁的「取消」 | 44pt 的可点区域在按钮里面；不要在 `Button` 外面加 `.frame(minHeight: 44)`，那只撑大布局，不撑大点按区域 |
| `CourtStatus` | 状态胶囊 | 三种语气：`live` 绿（数据在流动）、`idle` 灰（等待用户或另一台设备）、`warning` 橙（需要处理）。等待连接不是警告 |
| `CourtMetric` | 指标块 | 未知值显示「—」，不补 0 |
| `CourtMetricGrid` | 一组指标块 | 常规字号按最小宽度排成多列（默认 130pt），辅助字号下一列一块，不让「记录时长」「km/h」逐字折行。放指标块的网格都用它 |
| `CourtNotice` / `CourtErrorBanner` | 说明 / 可关闭的错误 | 错误必须给出下一步。iPhone 看板的错误横幅固定在顶部工具栏下，不随页面滚走 |
| `CourtNoticeBanner` / `CourtBanners` | 可关闭的中性提示（`model.notice`：记录切换、离线补算完成、删除记录） | `raised` 底、ⓘ 图标、44pt 关闭按钮。各页面用 `CourtBanners` 把错误和提示放在同一处：iPhone 看板工具栏下、横屏右栏顶部、Mac 标题栏下、机位页签下、历史列表与详情顶部；不依赖是否有记录。提示按字数停留 6–20 秒后自动消失，错误不会。机位自己的提示（如「采集已停止…点「继续」」）需要操作，不自动消失，点「继续」后清除 |
| `CourtSessionSummaryCard` | 记录结束后的总结 | 页面最上方（iPhone 看板、横屏右栏、Mac 数据栏、机位记录页），`selectedStroke` 描边的卡片：「记录已保存」、名称与时长、击球 / 最高 / 平均三个 `CourtMetric`、有球速的拍数与标记数、动作分布（一条分段色条 + 色点计数）、「查看详情」（打开这条历史记录）和 44pt 关闭。只用保存的记录数据，缺值为「—」；关闭或开始下一次记录后消失。卡片显示期间，下面的球速、落点、动作、逐拍列表和全屏看板继续显示这条记录的数据（`WorkspaceModel.shownEvents`），并注明「上一次记录「名称」的结果，开始新记录后清空」，不会一结束就变成一屏「—」 |
| `CourtStrokeTag` / `CourtStrokeLegend` | 动作色点 + 名称 / 图例 | 文字用正文色，颜色只在色点上；球场落点图旁的图例用 `symbols: true`，色点换成落点的形状（`CourtStrokeMark`） |
| `TennisShotRow` | 逐拍列表的一行 | 色点 + 动作、球速、落点图标（`scope` / 虚线圈）、末尾 44pt 的 ▶ 图标；缺值时下面一行写出 `TennisReason` 短句（「球速：没看清球」），点一行才展开模型分数和引擎原文。读屏标签包含球速或缺失原因、落点状态。取片段的大小说明只在列表上方说一次 |
| `CameraHealthCard` | iPhone 与 Mac 看板的「机位与分析」 | 标题右侧是「正常 / 需要处理 / 等待采集 / 未连接」；下面四个关键值（电量、温度、倍率、分析落后）、需要处理的事项、标定与持拍手按钮；完整机位状态、识别状态、数据口径和人员检测折叠在「详细状态」里 |
| `courtField()` | 所有文本输入 | 两个平台同一样式，最小 44pt 高 |
| `courtStatusBarScrim()` | 无导航栏的滚动页 | 防止 iPhone 内容滚到状态栏文字下面 |

## iPhone 看板的版式

- 顶部一行工具栏：返回（切换模式）、连接状态胶囊（点按打开配对与连接）、历史记录。它固定不随页面滚动，所以动态字体上限设为 `accessibility1`，读屏标签不受影响。
- 没有连接机位时只显示一个连接引导和记录面板，不显示一屏屏的「—」。
- 连接后首屏是实时画面、三个关键数字（球速 / 落点 / 动作）和记录面板；三个数字块行为一致，都全屏打开对应的看板（测速牌 / 落点看板 / 动作分布）。
- 记录进行中，暂停 / 精彩 / 待复核 / 结束固定在底部控制条；辅助字号下回到记录面板里，暂停与结束排在辅助标记前面（横屏窄栏里不用滚动就能看到）。没有连上机位时「连接机位」是唯一的主按钮，「暂停」等连上后才是主按钮（Mac 同样）。
- 记录面板的名称与计时并排；放不下（辅助字号、长名称）时计时移到名称下面，不把名称挤成一行几个字母。
- 横屏（宽 ≥ 640pt、高 < 600pt）保持左右两栏：左栏画面与数据，右栏记录控制。顶行与竖屏工具栏用同样的返回按钮和连接状态胶囊（点按打开配对），未连接时另有「连接机位」主按钮。
- 全屏看板（测速牌除外）的状态行说明数据来源：实时数据 / 上一次记录「名称」/ 画面已停止 · 保留最近结果 / 已连接 · 等待采集 / 未连接机位。

## Mac 看板的版式

- 标题行：球场工作台、与 iPhone 相同的连接状态（机位实时 / 已连接 · 等待采集 / 未连接机位）、实时画面（连接后）、历史记录、配对与连接、更多。错误与提示在标题行下。
- 任何窗口宽度（最小 760pt）都分两栏，各自滚动：左栏是总结卡、球速与落点（够宽时并排）、最近击球（`TennisShotRow`，最多 8 行，更多点「全部 N 拍」）；右栏 310pt（窗口窄于 1050pt 时 280pt）是实时画面、记录面板和 `CameraHealthCard`。
- 没有连接机位时左栏只有一个「连接机位」引导（唯一的主按钮），右栏只有记录面板，不显示空的球速、落点与画面。

## 动作类别配色

散点与球场落点按动作着色，同时用形状区分，并提供图例，颜色不是唯一线索。球场落点图的形状由 `TennisStrokeKind.courtMarkPath` 画出（叉、加号、星形是有面积的实心形状，便于扫一眼看清），浏览器看板的 `markPath` 是同一套几何。落点标记半径 6.5pt，选中的一拍 9.5pt 并加白边、画在最上层；浏览器上最近一拍放大并加白边。

| 动作 | 颜色 | 散点与落点形状 |
| --- | --- | --- |
| 正手 | `#3987E5` | 圆 |
| 反手 | `#D95926` | 方 |
| 发球 | `#199E70` | 三角 |
| 截击 | `#C98500` | 菱形 |
| 高压 | `#D55181` | 五边形 |
| 落地击球 | `#9085E9` | 叉 |
| 喂球 / 待确认 | `muted` | 加号 / 星号（落点图上为五角星） |

以面板底色 `#131A16` 校验：相邻两色在色觉差异模拟下 ΔE ≥ 8.4，正常视觉 ΔE ≥ 19.3，均对底色有 3:1 以上对比度。旧配色中反手（青）与落地击球（蓝绿）ΔE 仅 5.0，几乎无法区分，已替换。品牌绿不再作为数据颜色，避免与选中态混淆。

## 无障碍

- **不逐字换行**：系统最大辅助字号下，任何文字都不能一行一个字（「ZACK / S / COUR / T」「开 / 始 / 采 / 集」）。放不下时换版式：并排改竖排（`ViewThatFits` 的最后一项是一行一个控件）、图标与标题分两行、装饰图标与标语收起；单行品牌字用 `lineLimit(1)` 加 `minimumScaleFactor`。中文按词折成两行可以接受。
- **固定在屏幕上的条**（看板工具栏、画面上的文字、测速牌）设动态字体上限，读屏标签不受影响；可滚动的页面不设上限。
- **点按区域**：所有可点控件至少 44×44pt，`frame` 与 `contentShape` 写在按钮的 label 里。图标按钮用 `CourtIconButton`，纯文字按钮用 `CourtTextButton` 或 `CourtLinkButton`。
- **只靠位置的图**：球场落点图对读屏是一个元素，读出「N 拍有落点」；上下轻扫（adjustable）逐拍选中，读出「第 7 拍，正手，约 112 千米每小时，远端半场发球区，约横 3.2 米、纵 18.0 米」，和点按一样会联动逐拍列表。没有球速时读「暂无球速」，不读 0。浏览器上每个落点是带同样说明的 `role="img"`。

## 文案约定

- 同一概念在机位、App 看板、浏览器看板三处用同一个词，见下表。修改时三处一起改，浏览器页面在 `Sources/CourtCore/Web/`。

| 概念 | 用这个词 | 不再使用 |
| --- | --- | --- |
| 采集、录像并分析的手机 | 机位 | 机位端、摄像头客户端、对端 |
| 显示数据、远程控制的设备 | 看板（浏览器上为「浏览器看板」） | 看板端、分析服务端、接收端、对端 |
| 一次从开始到结束的上场 | 记录：「开始记录」「结束」（确认「结束本次记录？」）「记录名称」 | 会话、分析记录、训练记录（代码里的 `CourtSession` 不变） |
| 近端 / 远端球员用哪只手 | 持拍手 | 拍型设置 |
| 保存过的记录 | 历史记录 | 历史与查询、机位上的历史 |
| 记录中的手动标记 | 精彩、待复核（两个按钮，三处相同） | 标记精彩、标记 |
| 记录状态 | 进行中、已暂停、已完成、意外中断 | 记录中、已结束、已中断 |
| 机位温度 | 正常、偏暖、偏高、过热 | 偏热、严重过热 |
| 连接建立中 | 正在确认机位… | 等待握手 |
| 对方断开 | 机位已断开（看板上）/ 看板已断开（机位上） | 对端已断开 |
| 球场识别 | 球场映射、自动识别球场 | 标定球场、四角标定（已没有手动标定） |
| 一次记录里的拍数 | 击球（「16 拍」）、「N 拍有落点」 | 击球候选（指标标题）、可映射落点候选 |

- 缺失原因用 `TennisReason` 的短句（「还在分析」「没看清球」「球速不可靠，未计入」「没看到球落地」「球先碰网」「落点不在已识别的球场上」「机位负载高，这拍未定位落点」等），App 与浏览器同一份文案，浏览器从机位的 JSON 直接拿。引擎原文（如「三维轨迹拟合残差过大」）和分类模型分数只在选中一拍后的详情里出现。
- 估计值不显示测量级精度：落点保留到 0.1 m 并写「约」，球速取整数并写「估计」或「模型估算」。
- 不写方位词（「右侧」「下方」）：竖屏和横屏的布局不同，直接写控件名，例如「点「开始采集」」。
- 错误必须给出下一步，例如「记录保存失败：…。检查存储空间后重试。」「机位温度偏高：把机位移到阴凉处、避开阳光直射，取下手机壳。」（充电本身会发热，不把接电源当作降温建议）
- 红色只用于 REC；错误、警告和结束按钮用橙色（`warning`），浏览器页面同样。
- 空状态只在一个地方说明原因，其余位置说明「出现数据后会显示什么」，或者在有数据前不出现（例如 iPhone 看板未连接机位时只显示连接引导；没有击球的历史记录只有一个「击球分析」面板，不是四个空面板）。
- 无法使用的按钮在旁边说明条件，例如「机位还在准备，稍候即可开始记录。」
- `apps/iphone/ZacksCourtUITests` 按可见文字和 `court.*` 标识查找控件。修改按钮、标题或状态文字时同步修改测试。
