# 落点恢复：下一步的工程改造计划

2026-11-06。规则层的小改动已经收益递减，这里写清楚接下来两条路的做法、成本和验收，供决定先后。
所有数字来自本机离线测量，参照是 S家 App 的导出，只说明「和它一致」，不是物理真值。

## 已经量到的（不再重复试）

| 结论 | 证据 |
| --- | --- |
| 近端界内外的一切损失都在「落点没被检出」 | 150 条近端参照里 62 条没落点；19 条参照出界里 16 条没落点；有落点时判罚基本正确（x ≤0.13 m、y ≤0.37 m，2/3 判对） |
| 不是球看不见 | 缺落点的 1.6 秒窗口里中位 178 个候选（有落点的是 198），没有一条是 0 |
| 不是飞行资格判定 | 25 条「到不了网」的碎片末态中位离地 1.8 m、0 条贴地，外推发散；跨行借落点最多救 5/76 |
| 不是缺帧 | 缺帧已修（重置 111→14、匹配 228→259、判出 68→75、有速 121→136），落点覆盖仍是 50–61% |
| 规则层试过的形状都不行 | 放宽 gap、先落点后击球、地面邻近门控、惰性落点检查、碎片换落点、跨行借用、局部触地 |

所以：**球在下坠接近地面时，轨迹断了**。

## 方向 A：下坠段关联（纯 Swift，推荐先做）

**假设**：断的原因不是候选不够，而是 `junctions` 用图像距离做贪心配对，在球速最高、位移最大的下坠段
最容易配错或配断；用飞行模型预测的位置做代价，能把这一段接起来。

**先读了代码，这条假设要修正（2026-11-06，本轮）**：`kink(A, B)` 并不是拿原始图像距离比——它对 A 的末段
和 B 的首段各拟合一条局部多项式（`localPoly`），在两条**外推曲线**之间找最近距离，用最小距离当代价。
也就是说配对代价**已经包含了外推**，只是外推是几帧的图像空间多项式，不是弹道模型。所以「改成用预测位置」
不是结构性改动，只是把外推器换成弹道——预期收益比原判断小，方向 A 的性价比下降。

**做法（最小版本，约 1 天）**：

1. 在 `junctions` 里给每条已有轨迹外推 1–3 帧的预测位置（fit 已是弹道模型，外推很便宜）；
2. 候选的代价从「距上一点的图像距离」改成「距预测位置的图像距离 + 与预测速度方向的夹角惩罚」；
3. 只在「轨迹末端且末段速度向下」时启用这条代价，其余保持原样（限制影响面）；
4. 用 trace 回放验证：同一份 trace 重放，行数/落点/判法逐项对比。

**验收**（预注册，全部满足才合入）：

- 夜场近端「有落点」从 88/150 升到 ≥105/150；
- 近端判对率不低于 94%（双打线）、无参照误判不增加超过 2 条；
- 三段开发/留出视频（test.MOV、double-test-003、0913-dsh）的落点覆盖不降；
- 速度快照旧（trace 回放耗时 < 5 分钟）。

**证否条件**：如果下坠段的候选里本来就没有球（用参照落点反投影到图像、60 px 内无候选的比例超过一半），
那么关联层无论怎么改都救不回来，必须转方向 B。

**这个先决问题已经有一半答案**：评审用参照落点反投影查了「链和双弧段扫描都漏掉」的 79 条——60 px 内
**没有候选的只有 23 条**，另 2 条出画，其余 54 条（68%）附近是有候选的。所以「候选在、配对不上」这一侧
是真的，方向 A 值得做；那 23 条（约 1/4）是检测的硬限制，任何规则都救不回，这也是方向 B 仍有意义的原因。

## 方向 B：球模型微调（周期长，需要环境）

评审已经指出上一次微调的问题，重做的要点：

1. **从官方权重开始**（`.local/speed-training/tracknet-smoke-20261028/checkpoints/ckpts/TrackNet_best.pt`，
   摘要与仓库 manifest 一致），不从任何已变差的副本开始；
2. 损失沿用作者的 WBCE，不用 MSE；
3. 伪标签要带阻力、包含缺帧区的难正样本、静止球与偏离弧线的难负样本；**不用 S家的落点当标签**；
4. 验证集按视频切分（`0913-dsh` 与夜场留出），不能与训练帧相邻；
5. 先在同一验证集上量基础模型，再量微调模型；候选数崩塌（45,135 → 4,208）要先解释再谈；
6. 环境：这台 Mac 目前没有 PyTorch，需要新建；单机 MPS 训练按天算。

**环境准备的实际进展（2026-11-06）**：官方权重和训练代码都在本机
（`.local/speed-training/tracknet-smoke-20261028/checkpoints/ckpts/TrackNet_best.pt`，136,190,877 字节，
摘要与仓库 manifest 一致；同目录 `TrackNetV3/{train.py,model.py,dataset.py}`）。用仓库运行时的 Python 3.12
建了 venv 并装好 torch，但**导入失败**：`libtorch_global_deps.dylib` 的 Team ID 与宿主 Python 不一致
（macOS 代码签名冲突），对 dylib 做 ad-hoc 签名也无效。下一步换一个非签名的解释器再试。

**已解决（2026-11-06，本节后补）**：`brew install python@3.12` 装了解释器，用它重建 venv 后
torch 2.15.0 可导入、MPS 可用；官方权重 `TrackNet(27, 8)` **strict 加载成功**（epoch 18，27 通道 = 背景 +
8 帧），MPS 上前向出 8 张 288×512 热图。训练环境打通，方向 B 可以开工。

**验收**：同一验证集上候选召回（对参照落点 60 px 内）比基础模型高，且三段视频的落点覆盖与判对不劣化。

**证否条件**：如果基础模型在留出视频上的候选召回已经很高（说明不是模型的问题），方向 B 放弃。

## 建议顺序

先做 A 的**证否实验**（半天）：用参照落点反投影查「下坠段的候选里有没有球」。有 → 做 A 的完整版本；
没有 → 转 B，并同时接受「近端覆盖短期内不会大幅提升」这个事实。

无论哪条，都不动判罚规则（它已经被证明是对的），也不再用 S家的落点当训练标签。
