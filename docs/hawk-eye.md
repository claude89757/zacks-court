# 界内外：单机位界内外估计

> 这个功能在 App 里叫「界内外」。2026-11-03 以前叫「鹰眼」，因为 Hawk-Eye 是注册商标，上架前改了名；代码里的类型名（`HawkEye`）和无障碍标识（`court.hawkeye.*`）没有改。

> [!IMPORTANT]
> 界内外是一台手机、一个机位做的**模型估计，不是判罚**。正式比赛的电子判线系统用 8–12 台高速相机三角测量，标称误差约 3 毫米；我们一台手机的落点误差在近端约几厘米到二十厘米，远端更大。所以落点离线在误差范围内时，界面写「压线附近」，不报出界。

## 1. 用户看到什么

- **开启**：App 看板（顶栏、全屏测速牌）和浏览器看板（状态栏、测速牌）都有「界内外」按钮。关着时点按，会先弹窗问「本场是单打还是双打？」，因为两种比赛的边线不同。选完后界内外开启，默认**只判近端半场**。
- **设置**：开着时点按「界内外 · 单打」，可以改单打或双打、打开「也判远端半场」、开关「出界时语音播报 Out!」，也可以关掉界内外。远端默认关闭，原因见第 4 节。
- **提醒**：有一拍判出来后，看板顶部（全屏测速牌在底部）弹出一张卡，显示 4 秒，点一下就关：
  - **OUT**（红）出界，写「出界约 12 厘米 · 底线」；
  - **IN**（绿）界内，写「界内 · 距边线约 40 厘米」；
  - **CLOSE**（橙）压线附近，写「离底线不到 10 厘米，无法判定」。
- **声音**：只有明确出界才用英文人声喊「Out!」，和电子司线一样。界内和压线附近都不出声。
  - 声音是打包进 App 的录音 `Sources/CourtCore/Web/voice-out.m4a` 和 `voice-in.m4a`（挑战报「In.」用），App 和浏览器看板播同一份文件。App 在第一次报判定时（设好音频会话之后）载入，浏览器打开页面就预载，之后每次直接播放，不等语音合成启动。文件缺失时退回系统语音合成（en-GB）。换录音用 `scripts/prepare-line-call-voice.py out|in 原始文件`：裁掉首尾静音、峰值统一到 −1 dBFS、首尾淡入淡出、转成单声道 48 kHz AAC；提交录音时在这里写明来源（工具与音色、生成日期、授权，或录音人）。
  - iPhone 用播放类音频会话，静音开关打开时也会响，并且会压低正在播放的音乐。
  - 浏览器必须先点一下页面才能出声，所以开启界内外的那一下会顺便解锁声音。刷新页面后，如果界内外开着，会出现「🔈 点此开启 Out! 语音」。
- **同一拍只提醒一次**。之后这拍的落点被修正时，卡片上的判定会跟着悄悄更新，不会再喊一次。重新连接时补发的旧拍、超过 8 秒的旧拍都不提醒。

## 2. 判定规则

判定在**机位**上做，结果跟着逐拍数据一起发给所有看板，所以 App 和浏览器看到的永远一致，也保存在机位的记录里。看板只负责显示。

1. **判哪块区域**
   - 普通击球：判落点所在的那个半场（双打或单打边线、底线）。
   - 发球：判对角的发球区，用击球点的横向位置决定是哪一个；击球点太靠近中点，或不知道击球点（S家链），就两个发球区都算。双打的发球也只算单打发球区。
   - 靠球网的那条边不是线，不判。
   - 落点和击球在同一个半场的球（没有过网），不判。这一条要知道击球点：自研链每个有落点的拍都带击球点（两段开发视频上 162/162）；S家链没有击球点，这种球也会被判。
2. **离线多远**：用落点到线外沿的距离，减去球的半径 3.3 厘米。正数是整个球印都在线外，也就是出界；球印碰到线就算界内，和规则一致。
3. **误差范围** = max(3 厘米, 2 × 落点在这条线法向上的标准差)。距离在 ±误差范围内就是「压线附近」。
   - 自研链的标准差是两部分合起来：2 像素的图像误差通过地面映射的雅可比换算成米；再加上球在半帧（1/120 秒）里的地面位移，因为触地发生在两帧之间。
   - S家链只算触地热图定位的图像误差，取 3 像素（约一个热图格），通过单应性的雅可比换算成米。
   - 没有标准差时，误差范围取 15 厘米。

代码：判定在 `Sources/CourtCore/HawkEye.swift`，自研标准差在 `IndependentShotPipeline.bounceSigma`，S家链的落点外推和标准差在本地的参照链代码里（`.local/s-chain/`，见 [s-reference.md](s-reference.md)）。

## 3. 协议

都是协议 v2 内的可选新增，旧版本照常解码：

| 内容 | 字段 |
| --- | --- |
| 机位声明支持 | `hello.capabilities` 含 `hawkEye`；看板只对声明了的机位发命令 |
| 看板 → 机位 | `control`，`command: "hawkEye"`，`hawkEye: {enabled, format: "singles" \| "doubles", farHalf}` |
| 机位回显 | `status.hawkEye`，看板以此为准；回显前设置页显示「等待机位确认…」 |
| 判定 | `bounce.hawkEye: {call: "in" \| "out" \| "close", distanceM, marginM, line, format, serve, farHalf}` |
| 判定依据 | `bounce.sigmaXMeters`、`bounce.sigmaYMeters`；击球点 `hit: {x, y, z}`（只有自研链有） |
| 挑战（第 7 节） | 机位声明 `challenge`；看板发 `control`，`command: "challenge"`，可选 `shot`（拍的 ID，不带时机位自己挑）和 `format`；结果写在这一拍的 `challenge: {id, date, format, judgement?, reason?, pending?}` |

- 机位把设置存在存储目录的 `hawk-eye.json`。机位离开看板后重启，也按同一设置继续判。
- 每一拍按它被判时的设置判。中途开启界内外，之前的拍不补判；关掉后新拍不带判定。
- 两个看板设置不同时，以最后发到机位的为准，所有看板都会显示机位回显的设置。

## 4. 依据：误差有多大，为什么默认只判近端

我们在两段开发视频（test.MOV、double-test-003）上，用自研链的落点和上面的标准差公式测了一遍。近端的数字来自机位一侧的半场，远端来自对面半场。标准差和「压线附近」的比例是规则 v23 时测的；和 S家 App 的对照是规则 v25 重测的（2026-11-03），落点规则在两版之间没有变。

| | 近端 | 远端 |
| --- | --- | --- |
| 落点标准差中位数，横向 x | 0.04–0.05 米 | 0.05–0.06 米 |
| 落点标准差中位数，纵深 y | 0.20–0.21 米 | 0.31–0.80 米 |
| 落在误差范围内、显示「压线附近」的比例 | 3–6% | 21–24% |
| 能判的拍里，和 S家 App 判法一致（回放，两段合计） | 44/45 | 18/20 |
| 不留误差范围、直接按几何判，和 S家 App 一致 | 46/47 | 21/25 |
| 这台 Mac 上整条机位链实跑 test.MOV，能判的拍里一致 | 28/28 | 13/13 |

- 远端看得斜，纵深误差是近端的几倍。离机位较低的 double-test-003，远端标准差到了 0.8 米。所以默认只判近端。
- 「和 S家 App 一致」只说明两个软件的结论相同，不说明谁对。线附近的样本只有 5 个左右，没法按距离分段评估。真实误差要按[球场实测方案](field-test-plan.md)用独立参考核对。
- **覆盖率是现在的主要差距**：S家 App 在这两段里判了 75 + 103 个球（界内或出界），我们能给出判法的只有 36 + 36 个（Mac 实跑 test.MOV 是 44 个）。其余大多是我们识别到了这一拍，却没找到它的落点，S家 App 判出界的 27 个里也有 20 个是这样。所以「一致率高」只说明判出来的那部分可靠，不说明出界球都能喊出来。
- 对照用的是可选测试 `HawkEyeReferenceComparisonTests`（`COURT_HAWKEYE_COMPARE`，见 AGENTS.md），它对回放结果和 S家 App 导出行按击球时刻配对，再走一遍 `HawkEye.annotate`。
- 机位实时链上的提醒延迟：在这台 Mac 上用 `court-probe live` 按原速回放 test.MOV，整条机位链（自研实时链 + 会话 + 界内外）从球触地到判法出现，中位数 0.87 秒，九成在 1.01 秒以内。要等实时窗口把这段飞行拟合完。这是 Mac 上的回放，iPhone 上的延迟还没实测。
- Mac 实跑和回放是同一段视频的两次独立检测（实时链有少量不确定性），44 和 36 的差别不是规则变化。

## 5. 和 S家 App 的做法比较

- S家 App 导出的落点和界内外标签几乎总是一致；我们的判法只从落点坐标和误差范围算出来。
- 它的实时判线功能可以选关闭、半场（机位一侧）或全场，也可以选区域。它只喊「Out」，并提示远端可能不准。这两点我们照着做了：默认近端，只喊 Out。
- 它没有「压线附近」。我们给出误差范围，是因为单机位在线附近确实分辨不了。

## 6. 界内外回放与回放

正式比赛的电子判线回放有固定的节奏：挑战标题；三维轨迹从击球飞向落点；镜头推近到线；画出算出来的球印（不是拍出来的照片）；给出 IN 或 OUT，有时附上离线的距离。我们照这个节奏做：

- **入口**：
  - 有人挑战时（第 7 节），所有屏幕自动打开这一拍的回放；
  - 全屏测速牌标题行的「回放」（App 和浏览器都有），本场有判过或挑战过的拍时显示，打开后默认是最近一拍，可以前后翻，点「重播」再看一遍。
- **节奏**（约 5.8 秒）：
  1. 「CHALLENGE」标题，1 秒，背后是广角；
  2. 飞行与绕行：镜头从击球一方的底线后上方出发（整片场地入画，略偏向落点的另一侧），一边看球沿轨迹飞向落点、再弹出一小段，一边绕到落点旁边的四分之三视角，2.4 秒；
  3. 下沉：镜头继续绕到场内、贴近地面（眼高约 0.4 米起，离线越远越高），隔着被判的那条线看落点，线在画面里大致横着，1.6 秒。三台虚拟相机用一条平滑曲线（Catmull-Rom，两头缓入缓出）连起来，不是直线推近；
  4. 压痕：球印 0.5 秒内压出来，落地那一刻有一个半透明、略压扁的球，旁边标「约 N 厘米」（压线附近不标数字）；外面一圈虚线是误差范围（法向取判定用的误差范围，沿线方向取 2 倍标准差）；
  5. 结论卡：IN / OUT / CLOSE、离线距离、「模型估计，不是判罚 · 误差范围 ±N 厘米」。
- **球印和判定一致**：判定按球心周围半径 3.3 厘米的圆量离线距离，所以画出来的球印在垂直于线的方向上就是这个半径，只沿线方向拉长（球越是顺着线飞，拉得越长，最多 1.9 倍）。这样画面上球印到线的距离永远和结论卡上的数一样；顺着法向飞来的球（比如底线）球印接近圆形。
- **立体感**：没有用三维引擎（App 要支持 iOS 17，浏览器看板可能在没有外网的热点下打开），仍是同一套针孔相机投影加二维画布，靠这些纵深线索：
  - 固定方向的光（左上方、略从近端后方来）：球在地上的影子随高度变大变淡，球有高光和缝线，网和网柱在地上投影；
  - 夜空到地平线的雾化渐变，场外地面、缓冲区、球场三层颜色，画面四角压暗；
  - 落点附近 7×7 米撒了固定的细小颗粒，越远越小，地面因此读得出是一个平面；
  - 球网有网格、白色网带和两根网柱；
  - 轨迹是越靠近球越亮、越粗的拖尾，离镜头太近的部分淡出；落地后的那段是经验系数推出来的，画成更淡的虚线。
  颜色常量 App 在 `HawkEyeReplayPainter.Palette`，浏览器在 `RP`，两边相同。
- **视频**：结论下面是机位剪出的这一拍视频（App 的单拍片段按钮，浏览器的 `/api/clip`），和回放互相对照。
- **轨迹是估算的**：用击球点和落点、两者的时间差，按抛物线（只算重力）连起来，触地后按经验系数画一小段反弹。它不是测出来的三维轨迹，只用来让回放看得懂。S家链没有击球点，只回放落点和线，不画轨迹。
- 系统设置了减少动态效果时，App 直接显示最后一帧。
- 代码：几何在 `Sources/CourtCore/HawkEyeReplay.swift`（场景、三台虚拟相机和镜头路径 `camera(along:)`、球印尺寸、近平面裁剪、球场线），App 画面在 `Sources/CourtApp/Views/HawkEyeChallenge.swift`，浏览器在 `Web/app.js` 的 `replayScene` / `replayCamera` / `drawReplay`，两边用相同的数和步骤。
- 检查画面：Mac 上 `COURT_MAC_SNAPSHOTS=<目录> swift test --filter HawkEyeReplayTests` 把 App 的回放画成 PNG；模拟器上先用 `court-probe demo-session` 写示例记录，再用 `TEST_RUNNER_COURT_UI_REPLAY_DEMO=<目录>` 跑 `testChallengeReplayDemo`，看板会把这条标着「演示数据」的记录当作刚结束的记录显示，测试打开全屏测速牌的「回放」逐帧截图。

和正式界内外的区别：正式界内外的轨迹和球印是多台高速相机测出来的，误差约 3 毫米，所以只画一个球印；我们是单机位估计，所以球印外面画出误差范围，落在范围内的写「压线附近」。

## 7. 挑战

正式比赛里，球员对司线的判罚有异议时可以「挑战」，大屏随即播放这一拍的回放。我们的场景通常没有司线，挑战就是「刚才那球到底出没出界？」：任何一块屏幕点一下，机位重新判这一拍，所有屏幕一起播回放、报结果。

- **入口**：
  - App 看板：顶栏和全屏测速牌标题行的「挑战」（Mac 的测速牌窗口也有）；
  - 机位手机：记录页的「挑战」；
  - 浏览器看板：状态栏和测速牌标题行的「⚑ 挑战」。
  - 机位声明了 `challenge` 能力（新版机位）时才显示。
- **不需要先开界内外**。界内外开着时按它的单打或双打判；关着时第一次挑战先问「按单打还是双打边线判？」，本场只问一次（App 按记录记住，浏览器存在本页的存储里）。
- **挑哪一拍**：最近一个有落点的拍。如果在它之后 3 秒内又有新的击球（还没算出落点），就挑这个新的，等它的落点（最多 3 秒 + 1 秒）。挑错了可以点「不是这一拍？挑战上一拍」，往前找上一个有落点的拍。
- **怎么判**：和第 2 节同一套规则，但**两个半场都判**（远端也判，结论卡写「远端半场，误差较大」），用挑战时的单打或双打，不改这一拍原来的界内外判定。结果存在这一拍的 `challenge` 里，随会话保存；回放和提醒优先显示挑战的结果。
- **判不了时**写原因，不硬给结论：
  - 落点还在算：「落点还在计算，稍等片刻」，转圈，算出来后自动换成回放；
  - 没找到落点：「这一拍没找到落点，无法判定界内外」；
  - 没有过网：「这一拍没有过网，不判界内外」。
- **所有屏幕一起看**：挑战的结果跟着逐拍数据发给所有看板。每块屏幕第一次看到某个挑战（不是重连补发的）就打开回放，盖在当前画面上（包括全屏测速牌）。回放走到结论时用英文人声报「Out!」或「In.」，每个挑战只报一次；「压线附近」不出声。语音开关和界内外的「出界时语音播报」是同一个。浏览器要先点一下页面才能出声：点「挑战」那一下会解锁；只是旁观的浏览器页面会显示「🔈 点此开启 Out! 语音」（界内外关着也显示）。
- **不计次数**：本 App 不做计分，也不限制挑战次数。
- 代码：选拍和判定在 `HawkEye.challengeTarget` / `HawkEye.judgeChallenge`（`Sources/CourtCore/HawkEye.swift`），机位处理在 `CameraSessionController.challenge`，App 在 `WorkspaceModel`（Challenges 一节）和 `HawkEyeChallenge.swift`，浏览器在 `Web/app.js` 的 Challenges 一节。
